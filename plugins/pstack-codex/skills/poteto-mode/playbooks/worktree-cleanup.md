### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `bash "$POTETO_SKILL_ROOT/scripts/worktree-audit.sh" [-b <pr-base-ref>] [repo-path]` (principle-build-the-lever). By default, the audit uses the default branch of the repository selected by `gh repo set-default`, even when that repository has no local Git remote. Pass `-b <pr-base-ref>` when PRs target another repository or branch. `MERGED` uses the local base ref and `REMOTE` uses the local tracking ref for the push destination. A merged PR can establish the merge when its head SHA matches the checkout and its target matches the expected repository and branch. When Git cannot resolve the default branch, use the GitHub repository’s default branch. If that evidence exists, proceed even when `MERGED=?`. Use the paths reported by `git worktree list` (principle-encode-lessons-in-structure). Resolve unknown ownership through the host's attached artifacts and active or pinned chats. Read only the identified threads through `read-thread.mjs` per `$POTETO_SKILL_ROOT/references/codex-runtime.md`.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or sidebar and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. If the cross-check leaves a candidate's usage unclear, fan subagents out to read only the identified chats' transcripts and report whether the chat is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). A pinned chat spawns arena and repro trees into sibling worktrees via background subagents, and those are in use even when their names never hit the sidebar. Pick each subagent's reasoning level for the job, per the Subagents section.
4. Check what the operation will preserve. `DIRTY` groups untracked and ignored directories. Expand an entry when you need to decide whether its contents can be discarded. Resolve an unreadable status before cleanup. Keep worktrees in use. For ordinary Git removal, account for tracked edits, untracked and ignored content, and unpushed commits before removing the checkout.
5. Prune the confirmed set. For a Codex-managed worktree, continue in the chat that owns it. In that chat, get the worktree's `identityKey` from `list_artifacts` and pass it as `root` to `archive_worktree`. The snapshot preserves tracked changes, unpushed commits, and non-ignored untracked files. Preserve needed ignored content separately before archiving. For an ordinary Git worktree, preserve needed content and remove only files confirmed disposable, then use `git worktree remove <path>` without force. If removal refuses, inspect and report the remaining content. Use `git worktree prune` only if metadata needs cleanup. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
